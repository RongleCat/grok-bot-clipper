# Grok Bot Clipper 技术与使用细节

纯浏览器扩展，分别提供 Chrome / Edge（Manifest V3）和桌面 Firefox 140+ 的独立构建。没有本地连接器，没有中转服务器，不读取桌面端的登录凭证。浏览器版 SDK 使用 Web Crypto、Fetch、Uint8Array 和 ReadableStream；头像形状、表情与动作直接复用本机 Grok Bot 0.70.2 桌面端提取的原始头像运行时，未重新拟合轮廓。

## 安装

```sh
npm ci
npm run build
```

打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式，选择「加载未打包的扩展程序」，选中本项目的 `dist` 目录。将 Grok Bot 固定到工具栏，点击授权登录，再选择 BOT。

打包：`npm run package`，生成 `artifacts/grok-bot-clipper-0.3.10.zip`。解压后加载其中的扩展文件夹。

Firefox：运行 `npm run build:firefox`，输出 `dist-firefox/`，不会覆盖 Chrome 的 `dist/`。测试安装时，在 `about:debugging#/runtime/this-firefox` 点击「临时载入附加组件」，选择 `dist-firefox/manifest.json`；重启浏览器后临时安装会失效。

`npm run package:firefox` 生成独立 Firefox ZIP 和标有 `unsigned` 的 XPI。普通 Firefox 用户长期安装需要 Mozilla 签名；可选择不公开上架、仅自行分发。当前产物未经签名。[完整 Firefox 安装与签名说明](firefox.md)。

Firefox 使用原生侧栏和常驻后台页；网页归档为正文 HTML，Chrome 保留 MHTML。两个版本共用 BOT、草稿、对话、采集和上传逻辑，但浏览器之间的登录状态、设置和本地材料不会自动迁移。

## 使用

- 框选文字、右键图片或链接，选择发送目标；也可以加入材料篮。
- 工具栏面板按截图、网页与文件、材料管理分组，所有采集功能直接展示。顶部 BOT 名称与头像可点击切换。
- BOT 列表可以搜索，用书签图标收藏；默认 BOT 单独标记。每个头像由桌面端原始动作调度器按 BOT 身份独立驱动；遵循系统减少动画设置。
- 设置中选择直接发送或先补充说明。补充框中 Enter 发送，Shift+Enter 换行，Esc 可关闭对话框；输入法选词的回车不会发送。
- 材料篮把多个选区、图片、网页或本机文件合并为一个任务；多标签页功能只采集用户选中的页面。
- 草稿显示正文、出处、附件和采集缺失情况。可编辑正文、移除附件、裁剪、箭头标注和打码，再查看最终发送内容。
- 侧边栏显示 BOT 最近回复并支持追问。先回填最近记录，再从对应 cursor 监听；断开后重连。
- 设置中配置默认 BOT、截图/网页各自的 BOT、域名规则、任务、文本/附件预算、长截图范围、主题和保留时间。团队列表可用时可切换工作区。

默认快捷键：macOS `Command+Shift+7` 截图，`Command+Shift+8` 保存网页，`Command+Shift+9` 快捷命令；其他平台使用 Ctrl。浏览器或系统占用的按键不会被覆盖，在浏览器的扩展快捷键页面修改；设置面板显示实际生效的组合。

## BOT 收到什么

1. 用户说明与任务预设。
2. 按编号组织的原始材料，标题、出处和可用的作者/语言/采集时间等信息。
3. 完整正文 Markdown、表格 CSV、独立代码文件、原图/截图、上传的原始文件；网页归档开启时附带 MHTML。
4. `context.json`：来源、材料编号、附件对应关系、选区定位、章节、图片说明、媒体时间点/可访问字幕、嵌入页面以及缺失情况。

单次消息文本默认限制为 48,000 UTF-8 字节。正文超过这个预算时，消息显示来源索引与节选，完整正文保留在附件；不会偷偷丢弃剩余正文。目录本身超出预算会拒绝提交。单文件本地上限不超过 128 MB、整个材料包不超过 512 MB；服务端可以有更低的限制，拒绝原因会保留。

截图默认可附带页面正文作为背景，用户可以在设置中关闭。长截图有明确高度上限；较大的图片拆成按顺序命名的 PNG，避免超出浏览器画布尺寸。打码会覆盖待上传 PNG 的实际像素，并移除该材料的页面原文、来源和其他附件，避免打码内容从文字或原文件中泄露；其他材料需分别检查。

## 界面与组件

界面采用 [ReUI](https://reui.io/components) 免费组件的布局和交互模式，适配为本项目的语义 HTML 与 CSS；来源、参考 TSX 和 MIT 许可证保留在 `vendor/reui/`。共用样式位于 `public/components.css`，没有远程组件运行时。

顶部「草稿箱」保存尚未发送的材料和说明；草稿中的「发送预览」只读展示打包后的内容；「BOT 对话」用于查看回复和继续追问。三者使用不同图标与页面说明，侧栏会恢复草稿箱或上次编辑的草稿。

网页分享中的“发送给其他 BOT”会在当前页面打开紧凑浮层，统一提供搜索和全部 BOT 动态头像；点击 BOT 即发送，支持刷新列表、Esc 和点击外部关闭。开启发送前补充说明时，在同一浮层进入补充步骤。

侧栏聊天使用固定顶部 BOT 工具栏、中央独立滚动记录和底部组合输入框。回复支持 GFM Markdown（标题、列表、任务项、引用、表格、链接、图片、代码块），代码支持高亮和复制。内容经 DOMPurify 清理后渲染，代码和表格仅在自身区域横向滚动。

设置按发送方式、采集与上下文、BOT 路由、外观与本机数据、快捷键、账户与工作区分组；分类导航会随页面滚动更新选中项，快捷键使用独立键帽和修饰键图标。修改自动保存，数字限制显示单位和范围校验。正文与图片编辑共用有内边距的展开组件。

## 发送与恢复

附件使用桌面端 0.70.2 协议中确认的 `BeginGrokBotAttachmentUpload`、预签名 PUT / multipart、`CompleteGrokBotAttachmentUpload` 流程。服务端要求使用云端主机时，按对应网关分块上传。没有猜测上传 URL，也不会把本机路径当作服务端附件引用。

每份草稿用固定 messageId，草稿与任务在一个 IndexedDB 事务中提交。附件完成状态和 multipart 检查点会保存。长上传在扩展的 offscreen 文档中执行，工具栏弹窗关闭或 service worker 休眠不会主动取消它。浏览器退出后，重开并授权可恢复安全阶段的任务。

「已受理」表示服务端确认投递，不代表 BOT 已执行完成。提交结果不明确时显示「投递待确认」，不自动重发；「检查状态」调用真实状态接口。NOT_FOUND 也不会被误当作成功。失败任务可手动重试。

## 权限与数据

- `activeTab` / `scripting`：用户触发后采集当前网页和截图。
- `contextMenus` / commands：右键和快捷键入口。
- `tabs`：显示可选择的标签页并绑定正确来源；不会自动采集所有标签页。
- `pageCapture`：保存 MHTML。归档通过短暂的后台扩展页完成。
- `offscreen`：图像、PDF 与长上传任务。
- `sidePanel`：回复与追问。
- `storage` / IndexedDB / `unlimitedStorage`：设置、草稿、材料、发送记录和恢复检查点。
- `downloads`：用户主动导出附件。
- `alarms`：授权轮询、队列恢复和到期材料清理。
- 固定云端权限用于 SDK、云端主机与已知对象存储；跨网站采集使用按需授权。

账户凭证默认只放在扩展受信任上下文的 `chrome.storage.session`。不会进入网页脚本、URL、日志、同步存储或材料包。只有用户启用「浏览器重启后保持登录」才保存到本机扩展存储；这不等于操作系统钥匙串加密。内容脚本不能直接读取设置和凭证。发送器和回复按账户隔离；工作区切换会中止活动任务。

材料默认保留 7 天，可调为 1～90 天。没有分析埋点或自建中转服务。发送的材料会交给用户所选 BOT 的云端服务；仅由用户操作触发。

正文提取会排除表单输入、密码字段、隐藏 DOM 等。**MHTML 是浏览器生成的原始网页快照，可能包含登录后页面、隐藏资源和页面自身的敏感内容；它不等同于净化后的正文。** 在发送草稿中可移除归档，或在设置中关闭 MHTML。

## 平台边界

- Chromium 原生 `contextMenus` 没有逐项头像图标接口，不能动态或静态地给每个 BOT item 指定头像。原生菜单用真实 BOT 名称；默认图标使用桌面端引擎生成的黑色头像；自定义选择器显示真实动态头像。不会以无法实现的原生菜单图标能力作承诺。
- 官方 SDK 授权协议沿用桌面端登录页面，授权完成后网站可能提示打开桌面 APP；取消该提示即可，浏览器扩展仍能完成登录，不依赖打开桌面 APP。
- SDK 暂未确认刷新令牌与服务端撤销接口；授权失效需要重新登录。退出登录清除本机凭证，不代表撤销云端令牌。
- 任意网站的完整 DOM、跨域 iframe、无限滚动、DRM 视频、闭合 Shadow DOM、浏览器受限页面和受保护 PDF 都不能保证读取。缺失会保留说明，并可通过截图或来源链接补充。
- 通用视频采集保留页面可访问的字幕、当前时间点和画面；内置社交平台可从公开页面数据中获取完整视频附件，但不保证每条作品均可取得，也不绕过网站鉴权或 DRM。
- PDF 保留原文件并尝试提取文字；加密或扫描 PDF 可能只有原文件。没有把 OCR 当作已完成能力。
- MHTML 能否由 BOT 直接理解取决于 BOT 侧支持，完整正文 Markdown 同时提供。
- Chrome 为主要实现目标，Edge 使用相同 MV3 API，但仍需在对应环境做发行前验收。Firefox 已提供独立构建；Safari 暂未适配。

## 开发与验证

```sh
npm test
npm run build
npm run test:fixture
npm run package
```

`npm test` 包含真实协议字段、PKCE、分片消息解析、上传顺序/检查点、上下文预算、DOM 采集、UI 交互、输入法、像素打码、长图分片与 IndexedDB 防重事务测试。DOM/UI 测试在 jsdom 中运行，像素测试使用原生 Canvas，不应将它们称为真实浏览器端到端测试。

`npm run test:fixture` 启动 `http://127.0.0.1:8788` 合成验收页，不含私人资料。真实 Chrome 与云端往返记录见 [验证记录](verification.md)。

主要代码：`src/background.js`（扩展调度）、`src/sdk`（浏览器 SDK）、`src/content`（采集）、`src/core`（上下文/图像/队列/存储）、`src/offscreen`（持久工作）、`src/ui`（面板）。

本项目复用 [grok-bot-sdk](https://github.com/RongleCat/grok-bot-sdk)；SDK 的 MIT 许可证随源码和构建产物提供。原开源头像引擎已移除；桌面端头像提取来源、代码哈希和权利说明见 [头像来源](../vendor/desktop-avatar/PROVENANCE.md)。该 SDK 不是官方 Grok Bot SDK。
