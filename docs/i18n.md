# Internationalization

Grok Bot Clipper localizes extension pages, webpage share menus, BOT pickers, capture overlays, context menus, notifications, accessibility labels, and generated material labels. BOT names, user instructions, collected page content, file names, replies, and code remain unchanged.

## Language selection

The default **Match browser** setting resolves the browser UI language. Users can choose a language in **Settings → Appearance and local data → Language**. The preference is stored with extension settings and applies to both Chrome and Firefox. An unavailable language falls back to English. Arabic, Persian, and Hebrew use right-to-left extension layouts; injected controls do not change the source webpage's language or direction.

The registry in [`src/i18n/locales.js`](../src/i18n/locales.js) contains these 55 locale codes:

```text
ar am bg bn ca cs da de el en en_AU en_GB en_US es es_419 et
fa fi fil fr gu he hi hr hu id it ja kn ko lt lv ml mr ms nl
no pl pt_BR pt_PT ro ru sk sl sr sv sw ta te th tr uk vi zh_CN zh_TW
```

## Runtime and files

- [`src/i18n/index.js`](../src/i18n/index.js) resolves locales, interpolates named placeholders, formats dates and numbers, and updates extension document `lang` and `dir`.
- [`src/i18n/locales/`](../src/i18n/locales/) contains JSON catalogs keyed by literal source text. English and Simplified Chinese are bundled; other catalogs load from extension-owned `locales/{code}.json` files as needed.
- Content scripts request the selected locale and catalog through `i18n.locale`. This message returns localization data only, without account settings, login credentials, or collected page content. Source webpages do not gain extension storage access.
- UI copy uses explicit `t('source text', { name: value })` calls. The application does not translate the entire rendered DOM. Dynamic values are escaped when inserted into HTML and remain user data.
- Language initialization handles out-of-order loading so an older request cannot replace a newer selection. Failed loading falls back to English.

Chrome and Firefox builds copy the UI catalogs to `locales/` and generate browser-native `_locales/{code}/messages.json` files using [`scripts/i18n-build.mjs`](../scripts/i18n-build.mjs). The native files localize manifest descriptions and keyboard command descriptions. The product name remains **Grok Bot Clipper**.

## Adding or changing copy

1. Add an explicit `t()` call for the complete sentence, including accessible labels, tooltips, placeholders, errors, and generated material labels. Use named placeholders such as `{name}` and `{count}` rather than joining translated sentence fragments. Never pass arbitrary user text to `t()`.
2. Add the source key to every catalog. Keep placeholder names identical across languages. Prefer count-neutral wording where the catalog format does not express grammatical plural forms.
3. Keep the four manifest metadata keys: `manifest_description`, `command_capture_region`, `command_send_page`, and `command_quick_command`. Descriptions must fit the 132-character manifest limit.
4. Run the coverage check and tests, then build both targets. Review narrow layouts, long translations, keyboard focus, and RTL controls in context.

```sh
npm run check:i18n
npm test
npm run build
npm run build:firefox
npm run lint:firefox
```

The direct coverage command is `node scripts/check-i18n.mjs`. It checks locale registration, missing or unknown keys, named placeholders, manifest metadata, untranslated Chinese in non-Chinese catalogs (Japanese allows Han characters), and untranslated Chinese literals in extension source. Site recognition selectors and regular expressions are not extension copy. A justified same-line `i18n-exempt: reason` comment may mark an intentional source constant that is translated at runtime or used to recognize native page text.

Automated checks do not replace browser review or linguistic review. The initial translations are machine-assisted; they have not all been reviewed by native speakers. Reports and contributions should include the locale, screen, source key, current wording, and suggested wording.

## Chrome Web Store listings

The extension's `_locales` files localize installed-extension metadata and commands. Chrome Web Store listing descriptions, screenshots, promotional images, support text, and privacy disclosures are separate publishing assets and need their own localized versions in the store dashboard. Generating catalogs does not publish listings or guarantee store approval.

Builds remain explicit local commands. This localization work does not add automatic build or release workflows.
